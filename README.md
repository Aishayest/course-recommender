# Course Recommender

Рекомендательная система выбора университетских курсов: подсказывает, что брать
в следующем семестре, с учётом требований handbook и реального шанса попасть на курс.

## Идея

Handbook описывает, что студент обязан пройти, но на регистрации приоритет
достаётся не всем. Система совмещает три слоя:

1. **Ограничения** — пререквизиты, кредиты, квоты категорий. Детерминированные
   правила, не ML: модель не должна предлагать невалидное.
2. **Релевантность** — content-based эмбеддинги описаний курсов плюс профиль
   студента, собранный из пройденных курсов с весом по оценкам.
3. **Доступность** — вероятность получить место, обученная на истории регистраций.

Итог — не топ-5 по релевантности, а портфель с запасными вариантами:
«бери A, но если не дадут — B закрывает то же требование».

## Структура

```
src/course_recommender/
├── domain.py              доменная модель: курсы, студенты, требования
├── conditions.py          дерево пререквизитов AND/OR и его вычисление
├── constraints.py         жёсткие правила handbook
├── recommend.py           сборка рекомендации с объяснением
├── data/
│   ├── canva.py           извлечение handbook из Canva
│   ├── handbook.py        учебные планы по семестрам
│   ├── requirements.py    требования по категориям
│   ├── electives.py       списки элективов: у каждой специальности свои
│   ├── registration.py    пререквизиты и тиры приоритета регистрации
│   ├── schedule.py        секции семестра: Enr/Cap, время, конфликты
│   ├── assemble.py        сборка Program: каталог + требования
│   ├── catalog.py         каталог курсов по всем семестрам
│   └── transcripts.py     истории регистраций (заглушка)
└── models/
    ├── availability.py    вероятность, что курс заполнится
    ├── embeddings.py      эмбеддинги курсов и студентов (заглушка)
    └── ranking.py         реранкер кандидатов (заглушка)
```

## Данные

Handbook выгружается из Canva по годам поступления:

```bash
uv run python -m course_recommender.data.canva --all
uv run python -m course_recommender.data.assemble --year 2026 --program "COMPUTER SCIENCE"
```

Технические элективы у каждой специальности свои: для CS засчитывается любой
непрофильный курс CSCI 200+ и ещё 16 курсов других департаментов, у робототехники
список закрытый из шести ROBT-курсов, у математиков это любой MATH 300+. Часть
списков handbook задаёт правилом, часть — перечнем, поэтому правила разворачиваются
в коды только по каталогу курсов:

```bash
uv run python -m course_recommender.data.electives --year 2026 --program "COMPUTER SCIENCE" \
  --catalog "Course Requirements ... Fall 2026.pdf"
```

```
COMPUTER SCIENCE (CS) / technical
   перечислено 16; правило: CSCI 200+
   курсов в каталоге: 27
```

Пререквизиты и приоритеты — из документа Registrar, который публикуется перед
каждой регистрацией:

```bash
uv run python -m course_recommender.data.registration "Course Requirements ... Fall 2026.pdf" \
  -o data/raw/requirements_fall2026.json
```

Один документ описывает один семестр, поэтому про весенние курсы из осеннего
файла не известно ничего. Вместе же они дают каталог целиком — 1191 курс за
11 семестров, из них 446 читаются только весной:

```bash
uv run python -m course_recommender.data.catalog "Course Requirements ... "*.pdf \
  -o data/processed/catalog.json
```

Условия допуска и тиры приоритета хранятся в каталоге по семестрам: и то и
другое между регистрациями меняется, и подставлять прошлогоднее молча нельзя.
Если документа за нужный семестр ещё нет, берётся последнее известное до него,
а состав курсов — по сезону: то, что читали три весны подряд, прочитают и
этой весной.

Расписание с числом записавшихся и мест — оттуда же, по одному файлу на снимок:

```bash
uv run python -m course_recommender.data.schedule "school_schedule_by_term.pdf" \
  -o data/raw/schedule_fall2026.json
```

## Модель заполняемости

Шанс попасть на курс раскладывается надвое: заполнится ли курс — и, если
заполнится, достанется ли место этому тиру приоритета. Первое измеримо и
обучено на истории регистраций, второе из имеющихся данных не выводится.
Разделение нужно затем, чтобы предположение не растворялось в общей формуле.

```bash
uv run python -m course_recommender.models.availability school_schedule_by_term*.pdf
```

Проверка — по семестрам: модель учится на том, что было известно до целевого
семестра, и предсказывает его. Эталонов два: правило, по которому система жила
раньше ("заполнялся полностью — заполнится"), и то же правило, переведённое в
вероятность, — иначе выигрыш в калибровке достался бы модели даром.

```
--- проверка на Fall 2026 (374 курсов с историей)
   модель                                 AUC 0.760  Brier 0.214
   эталон сейчас: заполнялся полностью    AUC 0.694  Brier 0.289
   эталон: среднее заполнение ≥ 100%      AUC 0.663  Brier 0.294
   константа: доля полных                 AUC 0.500  Brier 0.237
```

На всех трёх проверочных семестрах модель выигрывает и по AUC, и по Brier.
Точность при пороге 0.5 иногда ниже эталона, и это ожидаемо: калиброванная
вероятность не оптимизирует долю угаданных меток, а на несбалансированной
задаче эта доля и так мало что говорит.

Модель намеренно маленькая — логистическая регрессия на двух признаках. Это не
экономия, а результат проверки: бустинг на четырнадцати признаках выигрывает на
одном семестре и заметно проигрывает на другом, где обучающих строк меньше.
На 1808 наблюдениях сложная модель неустойчива.

```bash
uv run python -m course_recommender.recommend \
  --admission-year 2026 --program "COMPUTER SCIENCE" --school SCAI \
  --semester 3 --completed-through 2 \
  --catalog data/processed/catalog.json --term "Fall 2026" \
  --schedule school_schedule_by_term*.pdf
```

```
CSCI 231   Computer Systems & Organization       балл 0.98
   стоит в плане на этот семестр; приоритет: тир 1; в прошлый раз заполнен на 90%
   шанс получить место ≈ 95%   (семестров в истории: 2)

CSCI 435   Blockchain and Cryptocurrencies       балл 0.92
   закрывает позицию плана «Technical Elective»; приоритет: тир 1; в прошлый раз заполнен на 56%
   шанс получить место ≈ 95%   (семестров в истории: 1)
```

Вероятность заполнения курса даёт обученная модель, а доли мест по тирам
приоритета остаются предположением: в выгрузках видно, сколько человек
записалось, но не кто из них какого тира.

## Статус

Разобран handbook за 2023-2026: 79 из 80 связок "год поступления + специальность"
покрыты учебным планом или таблицей требований. Из них собираются Program с
каталогом курсов, требованиями по категориям и минимальными оценками, поверх
которых работает слой ограничений.

Условия допуска известны для 93% курсов плана — до сборки каталога из всех
документов их было 65%, и весенние курсы не имели пререквизитов вовсе.

Свободные позиции плана раскрыты в конкретные курсы: из 105 таких позиций выпуска
2026 списком закрыты 62. Не раскрыты общие элективы ("любой курс любой школы" —
множество без содержательного ограничения), профильные элективы GSB и технические
элективы математиков, химиков и биологов: у первых список лежит в таблице другого
формата, у остальных handbook его не приводит вовсе.

Не хватает трёх источников:

- **описания курсов** для content-based эмбеддингов — handbook и документ
  Registrar дают только названия. Из-за этого же часть списков элективов
  инженерных специальностей (ECE, MAE) остаётся нераскрытой: там курсы
  перечислены названиями без кодов, и сопоставить их можно только точным
  совпадением с каталогом.
- **кому досталось место**: вероятность заполнения курса уже обучена, но
  распределение мест между тирами приоритета по-прежнему задано руками
  (`TIER_PLACE` в recommend.py). Enr и Cap описывают спрос на курс целиком, и
  очередь по ним не восстанавливается ни одной моделью — нужны данные уровня
  студента.
- **снимки заполняемости во время регистрационной недели** — расписание с
  `Enr`/`Cap` показывает состояние до и после, но не скорость, с которой
  разбирают места: из 16 выгрузок почти все дублируют друг друга, а реальных
  промежуточных точек всего две.
