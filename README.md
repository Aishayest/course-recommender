# Course Recommender

Рекомендательная система выбора университетских курсов: подсказывает, что брать
в следующем семестре, с учётом требований handbook и реального шанса попасть на курс.

## Идея

Handbook описывает, что студент обязан пройти, но на регистрации приоритет
достаётся не всем. Система совмещает три слоя:

1. **Ограничения** — пререквизиты, кредиты, квоты категорий. Детерминированные
   правила, не ML: модель не должна предлагать невалидное.
2. **Релевантность** — content-based эмбеддинги описаний курсов плюс профиль
   студента, собранный из пройденных курсов с весом по оценкам.
3. **Доступность** — вероятность получить место, обученная на истории регистраций.

Итог — не топ-5 по релевантности, а портфель с запасными вариантами:
«бери A, но если не дадут — B закрывает то же требование».

## Структура

```
src/course_recommender/
├── domain.py              доменная модель: курсы, студенты, требования
├── conditions.py          дерево пререквизитов AND/OR и его вычисление
├── constraints.py         жёсткие правила handbook
├── audit.py               что студенту осталось до диплома
├── plan.py                сборка семестра: курсы, секции, время
├── recommend.py           сборка рекомендации с объяснением
├── data/
│   ├── canva.py           извлечение handbook из Canva
│   ├── handbook.py        учебные планы по семестрам
│   ├── requirements.py    требования по категориям
│   ├── electives.py       списки элективов: у каждой специальности свои
│   ├── registration.py    пререквизиты и тиры приоритета регистрации
│   ├── schedule.py        секции семестра: Enr/Cap, время, конфликты
│   ├── prepare.py         разбор источников в кеши и их загрузка
│   ├── assemble.py        сборка Program: каталог + требования
│   ├── catalog.py         каталог курсов по всем семестрам
│   ├── transcripts.py     разбор транскрипта студента
│   ├── grades.py          распределение оценок по курсам и секциям
│   ├── descriptions.py    описания курсов из каталога Registrar
├── models/
│   ├── availability.py    вероятность, что курс заполнится
│   ├── embeddings.py      близость курса к тому, что студенту заходило
│   └── ranking.py         реранкер кандидатов (заглушка)
└── web/                   интерфейс: FastAPI, шаблоны, дизайн-система
```

## Данные

Handbook выгружается из Canva по годам поступления:

```bash
uv run python -m course_recommender.data.canva --all
uv run python -m course_recommender.data.assemble --year 2026 --program "COMPUTER SCIENCE"
```

Технические элективы у каждой специальности свои: для CS засчитывается любой
непрофильный курс CSCI 200+ и ещё 16 курсов других департаментов, у робототехники
список закрытый из шести ROBT-курсов, у математиков это любой MATH 300+. Часть
списков handbook задаёт правилом, часть — перечнем, поэтому правила разворачиваются
в коды только по каталогу курсов:

```bash
uv run python -m course_recommender.data.electives --year 2026 --program "COMPUTER SCIENCE" \
  --catalog "Course Requirements ... Fall 2026.pdf"
```

```
COMPUTER SCIENCE (CS) / technical
   перечислено 16; правило: CSCI 200+
   курсов в каталоге: 27
```

Пререквизиты и приоритеты — из документа Registrar, который публикуется перед
каждой регистрацией:

```bash
uv run python -m course_recommender.data.registration "Course Requirements ... Fall 2026.pdf" \
  -o data/raw/requirements_fall2026.json
```

Один документ описывает один семестр, поэтому про весенние курсы из осеннего
файла не известно ничего. Вместе же они дают каталог целиком — 1191 курс за
11 семестров, из них 446 читаются только весной:

```bash
uv run python -m course_recommender.data.catalog "Course Requirements ... "*.pdf \
  -o data/processed/catalog.json
```

Условия допуска и тиры приоритета хранятся в каталоге по семестрам: и то и
другое между регистрациями меняется, и подставлять прошлогоднее молча нельзя.
Если документа за нужный семестр ещё нет, берётся последнее известное до него,
а состав курсов — по сезону: то, что читали три весны подряд, прочитают и
этой весной.

Расписание с числом записавшихся и мест — оттуда же, по одному файлу на снимок:

```bash
uv run python -m course_recommender.data.schedule "school_schedule_by_term.pdf" \
  -o data/raw/schedule_fall2026.json
```

## Аудит

Студент выгружает свой транскрипт, и система говорит, что осталось. До этого
она исходила из допущения "шёл строго по плану", а по плану не идёт почти
никто: курсы пересдают, берут не в свой семестр, закрывают элективом не то,
что сосед.

```bash
uv run python -m course_recommender.audit student_transcript.pdf \
  --catalog data/processed/catalog.json --term "Fall 2026"
```

```
кредитов: 198 из 240, осталось 42

не пройдено обязательных курсов: 2
   сем 7  CSCI 408    6 ECTS  Senior Project I
   сем 8  CSCI 409    6 ECTS  Senior Project II

свободные позиции плана: закрыто 5 из 10
   + сем 5  Natural Science Elective             закрыт: BIOL 101
   + сем 7  Technical Elective                   закрыт: CSCI 262
   - сем 8  Technical Elective                   вариантов: 37
   - сем 7  Social Science Elective              вариантов: 183
```

Каждый пройденный курс разносится по тому, что он закрывает: обязательную
позицию плана или свободную. Позиции с самым узким списком разбираются первыми
— курс, годный и на технический электив, и на открытый, уходит туда, где
замены меньше. Позиция, про которую handbook не говорит, чем её закрывают,
остаётся непроверенной и помечена отдельно: закрыть её наугад значило бы
показать диплом там, где его нет.

Год поступления, специальность и школа берутся из транскрипта. Если в файл
попала не вся выгрузка, аудит отказывается работать: по половине транскрипта
он объявит непройденными курсы, которые студент прошёл.

## Оценки

Institutional Research публикует распределение оценок по школам и семестрам:
средний балл, медиана, разброс и доли оценок вплоть до отсева. Это единственный
источник, где написано, чем курс заканчивается для тех, кто его взял.

Имени преподавателя в отчёте нет — есть только номер секции, поэтому оно
берётся из расписания того же семестра по паре "код курса + номер секции".
Считаем по лекциям: у секции есть ещё лаборатория и рецитация, ведут их другие
люди, а оценку ставит лектор.

```bash
uv run python -m course_recommender.data.grades UG_Grade_Report_*.pdf \
  --schedule school_schedule_by_term*.pdf --course "CSCI 231"
```

```
CSCI 231 Computer Systems and Organization  средний 2.23
   Fall 2025  секция 1  балл 2.39  n= 89  ушли  9.2%  Shinnazar Seytnazarov
   Fall 2025  секция 2  балл 2.19  n= 83  ушли 13.5%  Hashim Ali
   Fall 2025  секция 3  балл 1.99  n= 46  ушли  6.1%  Hari Mohan Rai
```

Разброс считается внутри семестра, а не между: между семестрами меняется
состав студентов, а внутри одного семестра секции идут по одной программе, и
разница — это про то, кто ведёт. Она велика: медиана разброса 0.25 балла, у
22% курсов с несколькими секциями он больше 0.5, а у WCS 150 достигает 1.8.
Для сравнения, между 100-м и 400-м уровнем курсов разница всего 0.15 балла.

В рекомендации оценки идут свидетельством, а не критерием: система советует по
нужности и шансу попасть, а чем курс кончался — показывает рядом. Советовать
курс за то, что там мягче ставят, — это выбор цели, а не свойство данных, и
делать такой выбор за студента она не должна. Если цель всё-таки такая, вес
поднимается флагом:

```bash
uv run python -m course_recommender.recommend --transcript student_transcript.pdf \
  --grades UG_Grade_Report_*.pdf --prefer-easy 0.4
```

## Модель заполняемости

Шанс попасть на курс раскладывается надвое: заполнится ли курс — и, если
заполнится, достанется ли место этому тиру приоритета. Первое измеримо и
обучено на истории регистраций, второе из имеющихся данных не выводится.
Разделение нужно затем, чтобы предположение не растворялось в общей формуле.

```bash
uv run python -m course_recommender.models.availability school_schedule_by_term*.pdf
```

Проверка — по семестрам: модель учится на том, что было известно до целевого
семестра, и предсказывает его. Эталонов два: правило, по которому система жила
раньше ("заполнялся полностью — заполнится"), и то же правило, переведённое в
вероятность, — иначе выигрыш в калибровке достался бы модели даром.

```
--- проверка на Fall 2026 (374 курсов с историей)
   модель                                 AUC 0.760  Brier 0.214
   эталон сейчас: заполнялся полностью    AUC 0.694  Brier 0.289
   эталон: среднее заполнение ≥ 100%      AUC 0.663  Brier 0.294
   константа: доля полных                 AUC 0.500  Brier 0.237
```

На всех трёх проверочных семестрах модель выигрывает и по AUC, и по Brier.
Точность при пороге 0.5 иногда ниже эталона, и это ожидаемо: калиброванная
вероятность не оптимизирует долю угаданных меток, а на несбалансированной
задаче эта доля и так мало что говорит.

Модель намеренно маленькая — логистическая регрессия на двух признаках. Это не
экономия, а результат проверки: бустинг на четырнадцати признаках выигрывает на
одном семестре и заметно проигрывает на другом, где обучающих строк меньше.
На 1808 наблюдениях сложная модель неустойчива.

## Подготовка данных

Источники системы — это два десятка PDF плюс выгрузка каталога. Разбор занимает
минуты, поэтому он делается один раз, а всё остальное читает готовое:

```bash
uv run python -m course_recommender.data.prepare --sources ~/Downloads \
  --descriptions --vectors tfidf
```

Команда находит файлы по именам, под которыми их отдаёт Registrar
(`Course Requirements ...`, `school_schedule_by_term*`, `UG_Grade_Report_*`),
и складывает в `data/processed`: каталог курсов, снимки расписаний, статистику
оценок, описания, обученную модель заполняемости и векторы.

Каждый слой необязателен. Чего нет — того нет: система работает и без него,
просто без соответствующих свидетельств.

## Интерфейс

```bash
uv sync --extra web
uv run python -m course_recommender.web
```

Студент загружает транскрипт — больше ничего вводить не нужно: год поступления,
специальность, школа и предстоящий семестр берутся из файла. Неполный файл
отклоняется с объяснением, нечитаемый тоже.

Дальше открывается аудит: полоса набранных кредитов, карта программы по
восьми семестрам и список того, что осталось. Каждая позиция плана окрашена
своим состоянием — закрыта, не пройден, ниже проходной, идёт сейчас, открыта,
закрывается любым курсом, не проверена.

По любому курсу открывается статистика: средний балл, секции с преподавателями,
доля ушедших и разброс между секциями. Секции с n меньше 15 показаны бледнее —
по десятку человек средний балл говорит мало.

План на семестр показывает неделю с расставленными парами: выбранная секция
залита, альтернативная — пунктиром, курсы без времени вынесены над сеткой.
Рядом список с тем, что каждый курс закрывает, и причины, по которым остальные
не вошли. Секцию можно сменить — план пересоберётся, и если выбранная не
сходится по времени с остальным, будет видно, что взялась другая.

На странице рекомендаций у каждого курса разобран итоговый балл: видно, сколько
весит каждое слагаемое и что из них вообще известно. Рядом три колонки
свидетельств — попасть на курс, оценки на нём, кто ведёт, — и в каждой написано,
откуда взята цифра. Веса слагаемых меняются ползунками и приходят параметрами
запроса, так что ссылкой на конкретный расклад можно поделиться.

Транскрипт — персональные данные, и на диск он не ложится: разобранное живёт
в памяти процесса, браузеру достаётся только случайный ключ. Закрыли
приложение — не осталось ничего.

FastAPI, а не Flask, по одной причине: pydantic уже в зависимостях, то есть
фундамент оплачен, а типизированные модели и самодокументируемый API ближе
к тому, как устроено остальное.

Интерфейс держится на одном правиле: **три визуальных регистра**. Сплошная
плашка — факт из данных. Пунктирная синяя — оценка модели, не персональный
прогноз. Штриховка с курсивом — данных нет, и ноль вместо них не подставлен.
Это то же различие, что проведено в коде, только видимое без чтения подписи.

## Выкладка

Приложению нужны питон, четыре зависимости и подготовленные данные — 16 МБ,
включая выгрузку handbook. Разбор PDF на сервере не делается: исходников там
нет, и собирать кеши надо локально командой prepare.

```bash
docker build -t course-recommender .
docker run -p 8000:8000 course-recommender
```

Образ подходит для бесплатных тарифов Render, Hugging Face Spaces, Fly и
Koyeb: адрес и порт берутся из переменных `HOST` и `PORT`, как требуют
хостинги. Памяти нужно около 200 МБ.

Одно решение стоит принять до публикации. Университет публикует распределение
оценок **без имён преподавателей** — в отчёте есть только номер секции. Имена
система восстанавливает, связывая отчёт с расписанием того же семестра, и на
открытом адресе это уже публикация того, что публиковать не стали. Собрать
данные без этой связи:

```bash
uv run python -m course_recommender.data.prepare --sources ~/Downloads --no-instructors
```

Статистика курса при этом остаётся, пропадают только имена и разбивка по
преподавателям.

## Релевантность

Из тридцати семи технических элективов все закрывают одну позицию и дают одни
кредиты. По нужности они неразличимы, и без понимания содержания выбор
сваливался на остаточный признак — куда легче попасть.

Описания берутся из публичного каталога Registrar: страница рисуется скриптом,
но ходит он в обычный JSON-метод, и описание приходит прямо в результатах
поиска.

```bash
uv run python -m course_recommender.data.descriptions
uv run python -m course_recommender.models.embeddings --transcript student_transcript.pdf
```

```
  0.16  CSCI 496   Generative Artificial Intelligence     похож на CSCI 390
  0.12  CSCI 471   Complexity and Computability           похож на CSCI 270
```

Курс релевантен, если похож на то, что студенту уже зашло: ищется самый
близкий из пройденных, а его оценка задаёт вес. Средний профиль по всему
пройденному пробовали — усреднение тридцати курсов даёт размытый портрет
«среднего студента специальности», и все кандидаты оказываются от него
одинаково далеко: разброс 0.03 против 0.12 у близости к ближайшему.

Способа два. TF-IDF считает веса слов по самому каталогу, не требует
зависимостей и объясним по словам. Эмбеддинги понимают смысл, а не слова, —
и это заметно:

```
TF-IDF:      MATH 407 Graph Theory — 0.00, объяснить нечем
эмбеддинги:  MATH 407 Graph Theory — похож на CSCI 270 Algorithms
```

У 31% курсов описания нет вовсе, и TF-IDF про них не может сказать ничего;
модель понимает их по названию. Взамен она тянет torch, поэтому вынесена
в extra, а векторы кешируются — кодировать две тысячи описаний на каждый
запуск незачем.

```bash
uv sync --extra embeddings
uv run python -m course_recommender.recommend --transcript student_transcript.pdf \
  --descriptions --relevance intfloat/multilingual-e5-base
```

Одна деталь, без которой модель бесполезна: у неё любые два текста похожи —
косинус случайной пары курсов 0.777 при разбросе 0.045. На таком фоне разница
между машинным обучением и этикой теряется, а в произведении «вес × близость»
оценка забивает содержание, и все курсы оказываются «похожи» на тот, где стоит
A. Вычитание среднего по каталогу убирает общую составляющую: косинус
случайной пары становится −0.006 при разбросе 0.183.

Чего у этого слоя нет — проверки. У модели заполняемости был эталон и три
семестра, на которых она его била. Здесь эталона не существует: «хорошая ли
это рекомендация» нельзя посчитать, пока не видно, что студенты выбирают на
самом деле. Поэтому вес релевантности в формуле полезности намеренно невелик
(0.2 против 0.6 у нужности), а в объяснении всегда написано, на что именно
похоже, — чтобы студент мог не согласиться.

## План на семестр

Ранжированный список — ещё не ответ: на регистрацию студент несёт набор.
Флаг `--plan` собирает его целиком.

```bash
uv run python -m course_recommender.recommend --transcript student_transcript.pdf \
  --catalog data/processed/catalog.json --term "Fall 2026" \
  --schedule school_schedule_by_term*.pdf --grades UG_Grade_Report_*.pdf --plan
```

```
      онлайн

  CSCI 423   пересекается по времени с CSCI 435
  CSCI 434   позиции «Technical Elective» уже закрыты
```

Сколько позиций каждого вида ещё открыто, берётся из аудита, а не из плана:
студент, который идёт не по расписанию handbook, иначе получил бы четыре
технических электива при трёх незакрытых позициях.

Планируется по лекциям. Лабораторные и рецитации в расписании есть, но их
номера с лекционными не совпадают — у PHYS 161 три лекции и тридцать
лабораторных, — поэтому практику студент выбирает сам, а система предупреждает,
если вариантов у неё мало.

Секция выбирается не наугад: когда лекций несколько, они идут по одной
программе за одни кредиты, и разница между ними — только время и преподаватель.
Предпочесть ту, где преподаватель раньше выводил группу лучше, — это не выбор
курса полегче, а выбор из одинакового.

Вероятность заполнения курса даёт обученная модель, а доли мест по тирам
приоритета остаются предположением: в выгрузках видно, сколько человек
записалось, но не кто из них какого тира.

## Статус

Разобран handbook за 2023-2026: 79 из 80 связок "год поступления + специальность"
покрыты учебным планом или таблицей требований. Из них собираются Program с
каталогом курсов, требованиями по категориям и минимальными оценками, поверх
которых работает слой ограничений.

Условия допуска известны для 93% курсов плана — до сборки каталога из всех
документов их было 65%, и весенние курсы не имели пререквизитов вовсе.

Транскрипт разбирается полностью: на восьми файлах сумма кредитов по разобранным
курсам сошлась с итоговой строкой самого транскрипта везде, кроме файла, в
который попала одна страница из двух — этот случай система распознаёт и
отказывается по нему считать.

Свободные позиции плана раскрыты в конкретные курсы: из 105 таких позиций выпуска
2026 списком закрыты 62. Не раскрыты общие элективы ("любой курс любой школы" —
множество без содержательного ограничения), профильные элективы GSB и технические
элективы математиков, химиков и биологов: у первых список лежит в таблице другого
формата, у остальных handbook его не приводит вовсе.

Не хватает трёх источников:

- **оценки только за два семестра** — Fall 2025 и Spring 2026, по пяти школам
  из семи. Этого хватает, чтобы показать студенту, чем курс кончался, но мало
  для выводов о том, устойчив ли разброс между преподавателями.
- **транскрипты как выборка**: для аудита одного студента хватает, но обучать
  на них реранкер нельзя — один транскрипт это не выборка, а отобранные курсы
  в нём не отличить от навязанных планом.
- **проверка релевантности** — сам слой построен, но измерить его нечем:
  нужны фактические выборы многих студентов, а не одного.
- **кому досталось место**: вероятность заполнения курса уже обучена, но
  распределение мест между тирами приоритета по-прежнему задано руками
  (`TIER_PLACE` в recommend.py). Enr и Cap описывают спрос на курс целиком, и
  очередь по ним не восстанавливается ни одной моделью — нужны данные уровня
  студента.
- **снимки заполняемости во время регистрационной недели** — расписание с
  `Enr`/`Cap` показывает состояние до и после, но не скорость, с которой
  разбирают места: из 16 выгрузок почти все дублируют друг друга, а реальных
  промежуточных точек всего две.
